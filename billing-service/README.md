# Billing Service

Billing manages order invoices. It is a separate service from `payment-service`, which owns payment attempts and sandbox payment outcomes. Invoice status does not automatically follow payment status; a trusted order/payment integration is needed for that workflow.

## Configuration

Set `JWT_SECRET_BASE64` to the same standard-Base64-encoded random secret as `user-service` (at least 32 decoded bytes). `JWT_ISSUER_URI` and `JWT_AUDIENCE` must also match the access tokens issued by `user-service`. Set `DB_URL`, `DB_USERNAME`, and `DB_PASSWORD` for PostgreSQL. Docker Compose runs this service on port `8087` and routes `/api/billing/**` through the API gateway.

## API

All invoice endpoints require a Bearer JWT. The JWT subject is the customer UUID; `ROLE_ADMIN` is required for invoice creation, issuing, voiding, and access to all invoices.

| Method | Path | Access | Purpose |
| --- | --- | --- | --- |
| `POST` | `/api/billing/invoices` | Admin | Create one draft invoice per order. Request contains `orderId`, `customerId`, `currency`, optional `taxRate` (percentage), optional `dueDate`, and `lines` (`sku`, `description`, `quantity`, `unitPrice`). Subtotal, tax amount, total, invoice number, and status are generated by the service. |
| `GET` | `/api/billing/invoices` | Customer / admin | List the customer's invoices, or all invoices for an admin. Supports `page` and `size` (maximum 100). |
| `GET` | `/api/billing/invoices/{invoiceId}` | Owner / admin | Retrieve an invoice. |
| `GET` | `/api/billing/invoices/by-order/{orderId}` | Owner / admin | Retrieve an invoice by order. |
| `POST` | `/api/billing/invoices/{invoiceId}/issue` | Admin | Transition a `DRAFT` invoice to `ISSUED`. |
| `POST` | `/api/billing/invoices/{invoiceId}/void` | Admin | Void a `DRAFT` or `ISSUED` invoice. |

An order can have only one invoice, including after that invoice is voided. The current order service does not expose an order-verification API, so invoice creation is restricted to admins and the service cannot independently verify order ownership or line prices. Connect a trusted order-service integration before automating invoice creation. This service records invoices only; it does not collect payments or issue refunds.

Health and readiness probes are available at `/actuator/health`.
